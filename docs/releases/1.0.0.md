# WCount 1.0.0

First-ever release of the `wcount` CLI on the NuGet gallery, plus a WinGet submission for Windows.

## What ships

`WCount` 1.0.0 is an installable `dotnet tool` (command `wcount`) built on the repaired, GNU `wc`-compatible CLI Contract:

- **Counts** — lines (`-l`), words (`-w`), characters (`-m`), bytes (`-c`), and maximum display width (`-L`). A flagless run counts words, lines, and bytes, matching GNU `wc`.
- **File lists** — `--files0-from` reads a NUL-separated list of input names, adopted verbatim from GNU `wc`; combining it with file operands is an error.
- **Totals** — `--total=WHEN` with `auto` (the default: a Total row for multi-file runs only), `always`, `only`, and `never`.
- **Output** — column-aligned numbers sized once per column across the table, the filename at the end of each row, an unlabelled row for standard input, and per-file errors printed to standard error while the remaining inputs are still counted (any failure exits 1).
- **Standard input** — with no files named, counts piped stdin.

## Library package freeze

Existing library consumers are unaffected but should know the release posture going forward:

- **WCountLib** remains installable at its last shipped version **3.0.0**. The package line is frozen: no new WCountLib versions will be published.
- **WCountLib.Abstractions** remains installable at its last shipped version **2.4.0**. It was folded into WCountLib in this repository and is likewise frozen with no successor package.
- No `WCount` package identifier ever reached the gallery before 1.0.0; this release is the first.

The `wcount` CLI (the `WCount` package) is the single shipped product going forward. Both frozen library packages stay available on NuGet at the versions above for consumers who depend on them.

## Install

```
dotnet tool install -g WCount
```

Windows users can also install through WinGet once the package lands in the winget-pkgs repository.
